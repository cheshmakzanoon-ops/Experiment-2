# Synthetic Procreate colour-profile fixtures

These files are generated by `tools/fixtures/make_procreate_color_fixture.py` using Python's
standard library. They contain **self-authored artwork, ICC headers and profile descriptions**.
No reference-app executable, original ICC payload, copyright string or original artwork is
embedded in the committed fixtures.

The numeric D50-adapted colourants and sRGB transfer parameters reproduce the values observed
in the public Avarel/silicate documents at commit
`0e12deb2ae1ffb152fc4a3d09add230590f52f68`. Those original files are fetched separately by CI.
`RealProcreateFilesTest` checks their complete file hashes, original 536-byte ICC payload hashes,
recognised profile, hierarchy counts and selected native mask pixels. There are two distinct
original ICC byte sequences; all five have the same inspected Display P3 colourimetry. The
document named `Reference_Blend_File.procreate` calls its profile `ColorspaceDerived`, which is
why a profile-name-only recogniser would miss it.

The authored ICC fixtures exercise ICC v4 parametric curve types 3 and 4. Profile names do not
determine recognition. The production recogniser accepts only bounded canonical sRGB/Display P3
matrix/TRC profiles with its declared quantisation tolerances; it is not a general ICC engine.

## Document and pixel oracle

`display-p3-derived.procreate` is a 64 × 48 synthetic image with four asymmetric colour regions,
a transparent corner and a partial-alpha corner. Its tiles are premultiplied BGRA in a rotated,
mirrored layout inside Apple's uncompressed LZ4 containers. Its PNG thumbnail is straight RGBA
tagged with the authored Display P3 ICC. The archive calls that profile `ColorspaceDerived`.

`display-p3-native.argb` contains all 3,072 expected straight native pixels as big-endian ARGB
bytes, after the explicitly generated tile premultiplication quantisation. The Android copies
are byte-identical. `fixture.json` records dimensions and hashes.

Rebuild from the repository root:

```sh
python tools/fixtures/make_procreate_color_fixture.py
```

Optionally add `--samples /path/to/silicate/demo_files` to verify both original profile hashes
without copying those payloads into the generated output.

## Independent colour expectations

LittleCMS 2.19, relative-colorimetric intent, yields these 8-bit conversions with both the actual
inspected profile and the authored type-3 fixture. The tests store these literal expectations;
they do not derive them by calling ArtFlow's own colour conversion. The Android test also checks
the actual platform decoder, including `getPixels` on a bitmap decoded with preferred Display P3.

| Native Display P3 RGB | Decoded sRGB RGB |
| --- | --- |
| 230, 70, 45 | 250, 49, 23 |
| 20, 180, 120 | 0, 183, 115 |
| 40, 70, 230 | 29, 71, 239 |
| 190, 30, 185 | 208, 0, 191 |
| Background: 240, 30, 90 | 255, 0, 86 |

One code value is allowed for these independent matrix/transfer quantisation differences. Native
P3 layer values, background values, alpha, persisted rasters and fresh-repository reloads remain
exact assertions. The all-pixel conversion comparison against Android allows two colour code
values while requiring exact alpha, including partial-alpha pixels.

These are import, calibration and storage contracts. They do not establish generic ICC support,
native Procreate export interoperability, arbitrary profile fidelity or wide-gamut screen output.
