### Subsequent controlled runtime investigation

The [collector investigation](ANDROID15_COLLECTOR_CONTROL_2026-10-24.md) identifies a supported
same-image diagnostic. The failing API 35 / 16 KB image uses CMC on its October 2024 kernel;
the passing API 36 / 16 KB image reports UFFD unavailable and uses CC on its July 2025 kernel.
The passing standard API 36 image uses CMC, so collector type alone is not a sufficient explanation.
Exact AOSP source confirms a boot-time force-disable flag with compatible boot-image recompilation,
while a later kernel change disputes the earlier UFFD incompatibility rationale. These are leads,
not a demonstrated cause of any individual crash. The new isolated control leaves this run's
application/tests and failures unchanged and must be judged from its own completed evidence.

## Superseded run 310 and exact PSD expectation correction

[Run 310](https://github.com/cheshmakzanoon-ops/Experiment-2/actions/runs/40114802628) targeted
`9cec03181941d5b2988d4b62e16b8c3890f3c30b`. It began at 17:09:03 UTC and finished

While it was building, an independent PSD probe established that unmatting the merged PSD preview
cannot always reconstruct the original partial-alpha RGB byte. The merged preview is quantized
over white. Editable layers remain exact. The one-file correction changes only the device oracle
to independently derived exact merged values; it keeps the PNG, editable-layer, rendered Artwork,
visible recomposition, storage, checksum and undo checks. No tolerance or production codec changed,
and all 250 device identities remain required.

| Original band | Exact decoded merged band |
| --- | --- |
| Native `AA823CA5` | `AA833CA5` |
| Standard `C66F4D8D` | `C66F4D8C` |
| Standard `8E2AC05A` | `8E29C05A` |

For source channel c and alpha a, the independently checked integer paths are
`stored=floor((c*a + 255*(255-a) + 127)/255)` and, for nonzero a,
`decoded=clamp(floor((255*(stored+a-255)+floor(a/2))/a),0,255)`.
Fully transparent merged pixels are canonical zero.
