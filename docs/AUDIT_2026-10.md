# ArtFlow deep audit, October 2026

This audit reviewed the app across ten areas: product and parity, brush engine, canvas GL and
input, layers and undo, selection and transforms, colour, import and export security, persistence
and recovery, UI and accessibility, and performance with test coverage. It records what was fixed,
how each fix was checked, and what remains open.

It is not a parity claim. [PROCREATE_PARITY.md](PROCREATE_PARITY.md) sets the acceptance gates, and
those gates need artist and physical-device evidence that this environment cannot produce.

## Method and limits

- **No Android SDK or device** was available in the audit environment. Android code was reviewed by
  reading it. Only the Android-free packages (`core/`, `domain/`) were compiled and tested locally,
  with the Kotlin 2.0.21 compiler from the Gradle distribution and JUnit 4.
- Each fix has a regression test. For the selection, brush preset, binary-plist budget and grayscale
  PSD fixes, the test was also run against the previous code and failed there, as expected. The
  colour, glTF and Procreate tile changes were not run against the previous code.
- The full build and the device matrix run only in CI. A `workflow_dispatch` run on the branch
  verifies Android compilation, lint, device tests and the artifact checks; its result is in the
  Actions history rather than this document.
- Procreate's handbook was not reachable from the audit environment, so Procreate-side comparisons
  come from memory and are marked as such.

## Open findings, highest impact first

Severity follows the audit: P0 means data loss, wrong pixels, a crash, or exploitable input; P1
means clearly wrong or missing core behaviour. "Android" means the fix needs CI or a device.

### P0

1. **Recovery failure can delete the only snapshot** (`CanvasViewModel.kt`, `CanvasRepositoryImpl.kt`).
   A failed autosave recovery leaves the editor in Ready, and the next Save deletes the snapshot.
   Fix: keep recovery blocking until resolved, and gate save on it. Partly fixed in `462e3c2`: a manual
   save is refused while an autosave awaits recovery, as the background and periodic saves already were.
   The recovery dialog's own blocking is unchanged. Android, checked by CI only.
2. **Painting on a text layer erases it silently** (`CanvasRepositoryImpl.kt:973-988`). Editing the
   text replaces the raster and clears strokes. Fix: block paint on text layers, or rasterise first.
   Android, small.
3. **The colour-profile control relabels without converting pixels** (`CanvasRepositoryImpl.kt`, `setColorProfile`).
   Fixed in `a36165f`, as decided: switching profile converts every layer, text colour and the background
   in one undoable step, and timelapse frames are recorded in sRGB. Still open: the picker and brush keep
   sRGB, so strokes drawn after a switch are stored unconverted (item 4); Procreate imports write their
   background without converting it (`LayerImports.kt:115`); adjustment parameters are not rescaled; and the
   round trip can be off by up to 9 codes in emulation. Android, checked by CI only; a device check is needed.
4. **The eyedropper and brush mix colour spaces** (`ArtFlowCanvasView.kt:2500`). Picking #FF8000 on
   a P3 canvas paints (255,119,0). Fixed in `95fd551`, with a lint fix in `05eca4b`: interface colours convert
   into the canvas's stored space at the boundary (`documentColor`), and stored colours convert back for the
   picker, the live stroke prediction and the background swatch (`displayColor`). Strokes, backgrounds, clears,
   Fill Layer, Recolor, shapes, fills, gradient stops (`3ec61e6`) and new or edited text all convert. sRGB canvases
   are unchanged. Open: the device lanes check that the app runs, not the colour values, so the converted output is
   not yet confirmed on a device. Run 194 (`3ec61e6`): all lanes passed except the API 35 16 KB repeat, which hit the
   same ART interpreter crash as run 191, and the API 36 tablet, which failed the two practice-pad timeouts that run
   188 also hit. Those tests use `BrushPractice` on an sRGB canvas, which the colour change does not touch; the tablet
   passed on runs 189 and 193, so this failure is intermittent, not yet a confirmed regression.

5. **USDC section counts allocate before their payload is checked** (`UsdReader.kt:341-355`). Fixed in
   `4a41be8`: a section may not declare more output than LZ4 can produce from its compressed bytes
   (about 255 times), so the reader refuses it before allocating. Legitimate expansion is unaffected,
   and the existing USD fixtures still read.
6. **Memory during preview and filters.** `separableConvolve` allocated twelve full-canvas float
   planes per call (`ImageFilters.kt:369-416`). `56cf197` halves that to six, with identical output,
   but each call still allocates six, and it runs on every composite for Gaussian and feathered
   layers. Pure Kotlin, medium.
7. **CI can pass with its real-file checks skipped.** Fixed in `1a49075`, as decided: the Procreate sample fetch
   retries three times and fails the job unless a `.procreate` document is present, and `RealProcreateFilesTest`
   fails rather than skips in CI. A script test keeps the step free of `continue-on-error`. Run 191 (`aac8a7e`)
   confirmed the gate: the Avarel/silicate `demo_files` folder holds `.procreate` documents, and the JVM run checked
   them without skipping. The device lanes depend on the fetch (`needs: build`), so a fetch outage stops them too.

### P1

8. **Palm rejection and touch-hold eyedropper change the brush colour** (`PointerGestureRouter.kt`,
   `ArtFlowCanvasView.kt:1752`). A resting finger or palm after the pen lifts starts a stroke, and a
   still touch of 500 ms changes the colour. Fix: latch a stylus-lift window and ignore finger
   contacts for about 1.5 s; gate the hold on finger-sized contact. Pure router logic plus Android, small.
   **Design note:** a time window alone was tried and reverted. It also blocks a two-finger undo that
   starts right after a pen stroke, which is common. The reliable fix needs touch contact size
   (`MotionEvent` touch-major), or a deferred-start state that waits to see whether a second finger lands.
   Still open.
9. **Empty or non-null selections in adjustments and transforms** (`LiveAdjustments.kt:63`,
   `LayerTransform.kt`). Fixed for clipboard, transform and adjustments: `3fae6f5` makes an empty
   selection select nothing in `LiveAdjustments.apply` and `AdjustmentPaint.mix`, which is the path the
   adjustment preview uses. The core test fails on the old code.
10. **Alpha lock is ignored by blur adjustments and Fill Layer** (`ImageFilters.kt:384`,
    `SelectionClipboard.fill`). Blur and adjustments are fixed in `043aeb7`. Fill Layer is fixed in `5600f3b`:
    with the lock on, it paints only pixels that already have paint and keeps each alpha. The clipboard
    controller now looks up the lock. The new clipboard tests need the new parameter, so they cannot run on the
    previous code; the Android call site is checked by CI.
11. **Fill anti-aliasing paints fill colour over ink edges** (`FillTool.kt:193-213`). The edge ring
    is a dilation with alpha proportional to neighbour count, not coverage. Fixed in `6b4bd0d`: edge
    coverage now comes from colour distance to the seed colour.
12. **Brush round tips have no anti-aliasing** (fixed in `071e87b`, a one-pixel rim; the other tip
    shapes keep their previous edges). Original note: (`Stamping.kt`, `StrokeRasterizer.kt`). At default
    flow every edge is hard. Fix: a one-pixel ramp to the radius. Pure Kotlin, small.
13. **Brush spacing uses nominal size**, so tapers and light pressure bead (`StrokeRasterizer.kt:371`).
    Fixed in `dc80a3c`: each step is a fraction of the diameter that dab will have, so light strokes no
    longer leave gaps. Full-pressure strokes keep their spacing, and the rendering regression tests pass
    unchanged.
14. **Velocity uses processing time, not event time** (`Stroke.kt:18`, `CanvasRepositoryImpl.kt:584`),
    so batched samples share a millisecond. Partly fixed in `d1f35fe`: a segment with no elapsed time keeps the
    speed of the last measured segment, instead of reading as a 1 ms gap that drives speed dynamics to their
    limit. `SharedTimestampVelocityTest` fails on the old rasterizer. Fixed in `d51cac4`: each continued sample
    carries its own event time, converted from the uptime clock to the wall clock, so batched samples have
    their real spacing. The first point of a stroke is now stamped with its touch-down time as well, in `753c297`.
    `StrokeClockTest` covers the conversion; the canvas wiring is checked by CI. Item 14 is fixed.
15. **PSD import: 16-bit and ZIP content** (`PsdCodec.kt`). Partly fixed in `74fbc16`, `cc8b095`,
    `44594e4` and `302151f`: merged images and layers decode RAW, RLE and ZIP at 8 and 16 bits, and ZIP
    prediction is undone on 8-bit data. Fixed in `8116cd7`: 16-bit ZIP with prediction is undone on whole
    samples, with the carry crossing the high byte, instead of being refused. Both new predicted cases fail on
    the old reader. The layout follows the usual horizontal-differencing convention and has not been checked
    against a file written by Photoshop, so that remains the confirmation step.
16. **Decompression budgets for Procreate tiles.** ABR is fixed in `2c18b23`. Entry reads are fixed in
    `c4eb965`: `ProcreateImport.kt` checked only each entry's declared size and then read the whole stream,
    so a deflated entry could expand past that claim. The read now counts inflated bytes against the same
    256 MB limit. Tile inflation was already capped at each tile's expected size, so tiles were not the gap.
    Pure Kotlin, small.
17. **Autosave can be cancelled and loses up to one interval of work.** The background flush is not
    awaited or protected from cancellation (`CanvasScreen.kt:391`, `CanvasViewModel.kt:1222`), and
    each autosave rewrites every layer raster. Partly fixed in `94cc203`: the background save on stop runs
    in `NonCancellable`, so closing the app cannot cut it short. Still open: the save is not awaited, and
    each autosave still rewrites every layer raster. Android, medium.
18. **Merging a pass-through group header orphans its members** (`CanvasRepositoryImpl.kt:1067-1081`).
    Android, small.
19. **Group masks are accepted but never applied** (`CanvasRepositoryImpl.kt:1517-1539`). Fixed in `9be2abe`:
    a masked group is a scope like an isolated one, so its members are merged, masked and blended as one
    layer, and a pass-through group with a mask merges its members too. `GroupMaskTest` covers both cases.
20. **Canvas crop, rotate and resize silently drop editable text** (`CanvasRepositoryImpl.kt`, `transformCanvas`).
    Fixed in `a36165f`, as decided: crop, rotate, resize and flip rasterise editable text. The glyphs stay and the
    layer stops being text. `setTextLayer` refuses a rasterised layer, and Add Text clears any leftover edit.
    Open: a text layer with no raster file loses its appearance; locked and hidden text layers are rasterised too;
    and the Gradle tests are checked by CI, not yet on a device.

21. **Undo does not restore the selection** (`CanvasRepositoryImpl.kt:2751`). Fixed in `4664194`: undo snapshots
    hold the active selection by reference, and restoring one puts it back instead of clearing it.
    `UndoSelectionTest` runs in the Gradle JVM suite, so it is checked by CI rather than the local harness.
22. **Stroke commits copy a full layer on the UI thread** (`CanvasRepositoryImpl.kt:682`, `:773`, `:796`).
    Android, medium.
23. **Liquify live preview is off at the audit size** (`ArtFlowCanvasView.kt:2895`), and the
    displacement pass runs on the UI thread. Android, medium.
24. **Stale blur jobs run to completion** after the preview is cancelled (`LiveAdjustments.kt`,
    `ImageFilters.kt`). Fixed in `a8a16fc`: Gaussian and motion blurs call a per-row checkpoint, and the
    live preview passes `ensureActive()` there, so a superseded preview stops within a row. Apply keeps the
    no-op default. The core side is covered by `CheckpointedBlurTest`; the preview wiring is compiled by CI only.
25. **Per-pixel boxing in blend modes** (`BlendModes.kt:48`, `:382`). Pure Kotlin, small to medium.
    Fixed in `861f5a8` and `3b6b467`: the Hue, Saturation and Colour-family modes no longer build and sort a
    list per pixel, and blended channels go into one reused array instead of a boxed `Triple` per pixel.
    Output is bit-identical to the previous code across seeded mode results. `blendChannels` keeps its public
    `Triple` result for callers and tests.
26. **Accessibility:** unlabelled sliders and switches, colour-only tool selection, and sub-48 dp
    targets on core controls. Compose, medium. Needs TalkBack on a device.
27. **About 660 hard-coded UI strings**, with 17 of 18 `strings.xml` entries unused and no
    translations. Large.

### Lower priority

## What is strong

- Copy-on-write undo with identity-checked commits, and one undo entry per committed stroke.
- Atomic writes with fsync and content-addressed rasters; fail-closed decoding on import.
- Premultiplied resampling and blending; separable selection feather checked against brute force.
- The pointer router state machine, tested by pointer id.
- The LZ4, LZO, PackBits and ABR decoders, which bounds-check every read.
- The sRGB transfer curve, P3 and sRGB matrices, and the HSV maths, which were exact over all colours.
