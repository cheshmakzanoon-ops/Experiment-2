## Part A - Undo history: 30 steps -> 250 (Procreate keeps up to 250) without exploding memory
Today (CanvasRepositoryImpl.kt ~2818-2970): `undoStack`/`redoStack` hold whole-document `Snapshot`s; layer rasters/masks are shared copy-on-write PixelBuffer references, and every raster edit clones the full layer (`beginRasterEdit` etc.), so each stroke pins a full-layer buffer (16 MB at 2048^2).
`MAX_HISTORY = 30` and a memory cap (min(192 MB, heap/4)) therefore allow only ~12 steps on a 2048^2 canvas. Only undo()/redo()/pushUndo()/rasterBytes()/restore()/clear paths touch the stacks (grep `undoStack`, `redoStack`, `Snapshot`, `snapshotCopy`).

Design to implement (improve it if you find a flaw; keep the COW semantics for everything else so nothing else changes):
- New pure class in core/pixels (JVM-tested), e.g. `RasterDelta`: the tiles (say 64x64) of an OLDER raster that differ from a NEWER same-size raster; `between(older, newer)` (identity => empty delta, differing size => null), `overlayOnto(buffer)`, `bytes`. Optionally deflate tiles if it pays off (transparent regions compress extremely well) but measure.
- History compaction: keep the newest N (e.g. 4) snapshots of each stack as they are (full COW references). For older ones, replace each layer's `raster` (and `mask`) with an archived form: a RasterDelta against the NEXT-NEWER snapshot's same layer plus a reference to that LayerData; the full buffer is dropped so GC frees it.
  Restore = find the nearest full buffer along the chain, copy it ONCE, overlay deltas from nearest to farthest (do not allocate a full buffer per chain link), then proceed as today. Layers present in only one neighbour, size changes, text layers (note: `LayerData.raster`'s setter clears `text`; preserve it), etc. stay full.
  Shared buffers between neighbours (property-only edits) must also release when the newer neighbour compacts: give them an EMPTY delta rather than leaving a dangling full reference that pins the buffer.
- Apply the same compaction to the redo stack (deeper = older relative to the neighbour toward the top). Memory accounting (`rasterBytes`) must count deltas and the pinned base buffers; keep a memory cap but make it count the compacted size, then raise MAX_HISTORY to 250.
- Invariants to preserve and test: undo/redo results are pixel-identical to the pre-change behaviour for any sequence of edits (write a randomized/property JVM test that drives a fake or the real repository through random edits and compares full-document hashes after undo/redo chains against an uncompacted reference run);
  masks and rasters; layer add/remove/reorder between steps; canvas resize between steps; interleaved redo then new edit (redo cleared).
- JVM tests for the repository itself (data/ tests: see CanvasMutationTest/UndoSelectionTest/StrokeCommitTest): they use android mock classes, so they are compile-checked by the Android harness if it exists and otherwise run only in CI. Put the pure delta logic and as much history logic as possible into core/ (pure, locally runnable) and keep repository glue thin.
- Memory/time: report numbers for a 2048x2048 canvas with 10 layers after 250 strokes (bytes retained, undo-to-the-oldest latency on this machine).

## Part B - Slider-driven history spam
Edits driven by sliders push one undo step per tick (mask density/feather RP ~1704-1735, adjustment-layer params ~1788, filter amount ~1848; only layer opacity coalesces via `opacityRun`). One drag flushes history. Coalesce each continuous drag into ONE step (generalise the opacity mechanism: e.g. a keyed edit-run that closes on a different action, undo/redo, or idle timeout). Test it.
